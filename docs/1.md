# 2. 数据源配置应该放业务服务

因为每个微服务本来就可能连接不同数据库。

例如：

```text
nova-system
    ↓
nova_system

nova-order
    ↓
nova_order

nova-file
    ↓
nova_file

nova-ai
    ↓
nova_ai + pgvector
```

所以每个服务自己的：

```text
src/main/resources/application.yml
```

或者 Nacos 配置中心里，应该保存自己的数据库连接。

例如：

```yaml
nova:
  datasource:
    db-type: mysql

spring:
  datasource:
    url: jdbc:mysql://localhost:3306/nova_order
    username: root
    password: 123456
```

切 PostgreSQL：

```yaml
nova:
  datasource:
    db-type: postgresql

spring:
  datasource:
    url: jdbc:postgresql://localhost:5432/nova_order
    username: postgres
    password: 123456
```

切达梦：

```yaml
nova:
  datasource:
    db-type: dameng

spring:
  datasource:
    url: jdbc:dm://localhost:5236/NOVA_ORDER
    username: NOVA_ORDER
    password: 123456
```

业务 Java 代码不用动。

# 3. 最好用 Spring Profile 切

你现在 POM 里已经有一句：

```xml
<!-- 使用 SPRING_PROFILES_ACTIVE=dev,pg 时需要 -->
```

说明你本来也打算通过 Profile 切 PostgreSQL。

可以正式规范成：

```text
application.yml
application-mysql.yml
application-pg.yml
application-oracle.yml
application-dm.yml
```

主配置：

```yaml
spring:
  profiles:
    active: dev,mysql
```

MySQL：

```yaml
# application-mysql.yml

nova:
  datasource:
    db-type: mysql

spring:
  datasource:
    driver-class-name: com.mysql.cj.jdbc.Driver
    url: jdbc:mysql://localhost:3306/nova_demo
    username: root
    password: 123456
```

PostgreSQL：

```yaml
# application-pg.yml

nova:
  datasource:
    db-type: postgresql

spring:
  datasource:
    driver-class-name: org.postgresql.Driver
    url: jdbc:postgresql://localhost:5432/nova_demo
    username: postgres
    password: 123456
```

达梦：

```yaml
# application-dm.yml

nova:
  datasource:
    db-type: dameng

spring:
  datasource:
    driver-class-name: dm.jdbc.driver.DmDriver
    url: jdbc:dm://localhost:5236/NOVA_DEMO
    username: NOVA_DEMO
    password: 123456
```

启动：

```bash
java -jar nova-demo.jar \
  --spring.profiles.active=prod,dm
```

就切达梦。

# 4. 驱动到底放 Starter 还是业务服务？

这里我推荐：

> **数据库驱动放业务服务，兼容逻辑放 Starter。**

你现在就是这种方式：`nova-demo` 自己引入 MySQL 和 PostgreSQL 驱动。

这是比较好的。

例如：

```xml
<dependency>
    <groupId>com.nova</groupId>
    <artifactId>nova-datasource-spring-boot-starter</artifactId>
</dependency>

<dependency>
    <groupId>com.nova</groupId>
    <artifactId>nova-mybatis-spring-boot-starter</artifactId>
</dependency>

<dependency>
    <groupId>com.mysql</groupId>
    <artifactId>mysql-connector-j</artifactId>
    <scope>runtime</scope>
</dependency>
```

如果某个客户使用 PostgreSQL：

```xml
<dependency>
    <groupId>org.postgresql</groupId>
    <artifactId>postgresql</artifactId>
    <scope>runtime</scope>
</dependency>
```

这样不会出现一个普通 MySQL 服务里同时带：

```text
MySQL Driver
PG Driver
Oracle Driver
DM Driver
```

全部塞进去。

当然你做 `nova-demo` 示例项目，为了演示切换，同时带几个驱动是可以的。

# 5. 多数据库兼容真正难的不是连接

连接切换非常容易。

真正难的是：

```text
SQL 方言
分页
关键字
函数
自增主键
Sequence
大小写
DDL
时间类型
JSON
批量插入
Upsert
```

所以建议你在：

```text
nova-datasource-spring-boot-starter
```

或者单独：

```text
nova-database-core
```

建立：

```java
public interface DatabaseDialect {

    DbType dbType();

    String currentTime();

    String concat(String... columns);

    String pagination(String sql, long offset, long size);

}
```

实现：

```text
MysqlDialect
PostgreSqlDialect
OracleDialect
DamengDialect
```

数据库类型：

```java
public enum DbType {

    MYSQL,

    POSTGRESQL,

    ORACLE,

    DAMENG

}
```

然后通过配置：

```yaml
nova:
  datasource:
    db-type: dameng
```

自动注入：

```java
DamengDialect
```

# 6. MyBatis Mapper SQL 尽量写通用 SQL

比如这种：

```sql
select
    id,
    username,
    create_time
from sys_user
where id = #{id}
```

四种数据库都很好兼容。

但不要业务里大量出现：

```sql
LIMIT 10
```

或者：

```sql
IFNULL(...)
```

或者：

```sql
DATE_FORMAT(...)
```

这种数据库私有语法。

分页交给 MyBatis-Plus。

空值处理尽量 Java 做。

复杂数据库差异才进入 dialect。

# 7. 实在没法通用的 SQL，可以按 databaseId 分开

MyBatis 原生支持 `databaseIdProvider`。

例如：

```xml
<select id="findPage"
        databaseId="mysql">
    ...
</select>

<select id="findPage"
        databaseId="oracle">
    ...
</select>

<select id="findPage"
        databaseId="dameng">
    ...
</select>
```

所以你的 Starter 可以统一配置：

```java
DatabaseIdProvider
```

数据库自动识别：

```text
MySQL      → mysql
PostgreSQL → postgresql
Oracle     → oracle
DM         → dameng
```

这比代码里到处：

```java
if (mysql) {

} else if (oracle) {

}
```

专业很多。

# 8. ShardingSphere 又是另一维度

一定不要把：

```text
数据库类型
```

和：

```text
是否分库分表
```

混在一起。

正确模型：

```yaml
nova:
  datasource:
    db-type: mysql
    mode: single
```

或者：

```yaml
nova:
  datasource:
    db-type: mysql
    mode: sharding
```

或者：

```yaml
nova:
  datasource:
    db-type: postgresql
    mode: read-write-splitting
```

所以：

```text
db-type
    ↓
决定数据库是什么

mode
    ↓
决定怎么访问数据库
```

模式：

```text
SINGLE

READ_WRITE_SPLITTING

SHARDING

SHARDING_READ_WRITE
```

# 9. Nacos 最后负责外部化配置

真正企业部署时，业务服务最好不要把密码写在 Jar 里的 YAML。

比如：

```text
nova-order
        ↓
      Nacos
        ↓
nova-order-prod.yaml
```

里面：

```yaml
nova:
  datasource:
    db-type: mysql
    mode: sharding

spring:
  datasource:
    ...
```

客户A：

```text
MySQL
```

客户B：

```text
达梦
```

代码完全相同。

只换 Nacos 配置 + JDBC Driver。

这就是真正意义上的“多数据库可切换”。

# 10. 我建议你把现在结构改成这样

```text
nova-starters
│
├── nova-datasource-spring-boot-starter
│   ├── config
│   ├── properties
│   ├── dialect
│   │   ├── MysqlDialect
│   │   ├── PostgreSqlDialect
│   │   ├── OracleDialect
│   │   └── DamengDialect
│   └── autoconfigure
│
├── nova-mybatis-spring-boot-starter
│
└── nova-shardingsphere-spring-boot-starter
```

业务：

```text
nova-business
└── nova-demo
    ├── src/main/java
    └── src/main/resources
        ├── application.yml
        ├── application-mysql.yml
        ├── application-pg.yml
        ├── application-oracle.yml
        └── application-dm.yml
```

依赖关系：

```text
                    nova-demo
                       │
          ┌────────────┼────────────┐
          ↓            ↓            ↓
   mybatis-starter datasource   sharding-starter
          │         starter          │
          └────────────┬─────────────┘
                       ↓
                 DataSource
                       ↓
       MySQL / PG / Oracle / Dameng
```

所以回答你的核心问题就是：

> **数据源“连接配置”应该属于业务服务，因为每个微服务自己的库不一样；数据库兼容“能力”必须放 Nova Starter，业务服务不应该自己实现。**

这样以后别人复制你的 `nova-demo` 做 `order-service`，只要改：

```text
数据库URL
账号
密码
db-type
Driver
```

基本业务代码完全不用改。
